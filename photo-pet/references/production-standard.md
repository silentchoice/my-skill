# 照片宠物制作规范

## 固定身份，尽早确认可读性

查看真实参考文件再生成；路径有误时先查找用户指明目录中的合理候选，不把不存在的 `.jpg` 当作输入。锁定一张全身主参考，用于全部动作；真人角色保持自然头身比、肤质、头发和衣料。先在 192×208 的实际显示尺寸检查脸部、手势及身体完整性。选择不与衣服、皮肤、饰品冲突的色键，保存在 pet_request.json；不要固定使用青色或绿色。

行提示词只表达角色、动作阶段、帧数、方向、完整身体、安全留白、固定灯光和背景约束。附主参考及布局参考，注明布局线不属于画面。透明边缘无描边、外发光、底座阴影或游离动作符号。不要把整份流程和 QA 规则塞入生成提示词。

## 按依赖推进

1. 使用 hatch-pet 和 imagegen 创建主参考，建立独立 run 目录、pet_request.json 与 imagegen-jobs.json。
2. 制作各标准动作，先检查最小动作行，合格就记录来源并复用。右移先于是否可镜像左移的判断；服装、饰品或持物有方向性时不得盲目镜像。非方向性 running 表示工作处理中，不是原地跑步。
3. 标准行通过后建立上、右、下、左四个方向基准。000 是向上，不是正面静止；neutral 使用独立默认姿势。
4. 先生成并注册完整 row 9，再把已通过 row 9 和四方向基准附给 row 10。保持顺时针顺序，每行只使用一次完整八姿势生成的内容。
5. 全部行按依赖通过后组装、执行一次必要的透明边缘清理、验证、输出 APNG，再打包和按任务范围安装。

## 尺寸校正的边界

观察原始行和最终格子，区分生成比例不同与逐帧适配引发的跳动。若同一行内部稳定、方向正确，仅整行比另一行小，按本用户指定的规范优先从**原始分辨率姿势**统一校正，不重生成已合格内容。

- 以 neutral 和已通过的 row 9 为目标，测量身体高度、脚底基线、下半身中心及全部姿势的左右范围。
- 对待修正完整行求一个共同缩放因子；全部姿势使用该因子，只做必要平移对齐。保留原始比例、帧顺序和另一行。不要分别把每帧填满格子，也不要放大已经缩小后的 192×208 格子。
- 使用 hatch-pet 当前脚本的真实接口。`assemble_extended_atlas.py` 的 `--registered-row-9` 路径把 `--row-9-registration` 的 scale 应用到原始 row 10，而 row 9 直接复用注册格子。若需要独立的 row 10 因子，保存一个**另命名的校正 manifest**并在说明中记录该参数兼容用途，不覆盖真实 row 9 注册记录，不声称存在 `--row10-scale` 参数。
- 记录来源行哈希、目标参考、共同因子、基线、原始注册文件、校正 manifest 和适用的用户规范。执行后重新检查边缘、完整轮廓、16 方向语义及循环连续性；共同因子仍无法同时解决大小和裁切时，修复该完整源行。

这项布局约定补充 hatch-pet 的 row 10 固定变换默认规则，其他验收不变。不得用它旋转整个身体假装看向某方、改变五官或拼接单独重生的姿势。

## 验收与停止条件

结构：最终 1536×2288，8×11 个 192×208 格子，spriteVersionNumber 为 2；实际已用格、neutral 专用格及透明空格遵循 hatch-pet 当前 schema。完整的 8×9 标准图集仅是中间产物。

视觉：9 组动作身份一致、各有用途且循环可读；视线四个主方向清楚，斜方向有对应水平和垂直趋势。按 hatch-pet 执行独立方向 QA，裁切、身份漂移、错误象限、循环逆转、明显尺寸跳变均阻止交付。细微斜向相似或衣物遮住部分步伐可在有依据时记录为 warning，不能照抄历史角色的豁免。

透明：最终色键清理和图集检查通过即结束该轮色键 QA。预览光晕先检查编码，不重复侵蚀轮廓、清理或重生成。APNG 的像素与时间验证和上述内容检查相互独立。

提速来自复用真实完成且匹配当前输入的结果、尽早检查最小失败行，以及确定性组装和导出；不跳过必要动作或检查。依赖链以外的工作按可用工具规则安排，避免无意义的重复生成和轮询。
